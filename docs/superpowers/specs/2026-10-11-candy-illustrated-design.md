# Candy, illustrated: original artwork for the site's look

**Date:** 2026-10-11
**Status:** Approved in conversation. Vikrant compared three directions on a review page (A: keep the layout, add original artwork; B: a pond-world restyle; C: arcade tiles) and chose A, with both optional parts included: icons on the game-page titles, and the retirement of legacy gradients.

## Goal

The site's layout, palette and type already work. Its pictures do not: every game icon is an emoji drawn by the visitor's operating system (so it differs on Windows, Apple and Android, and two games share 🔢), the hero is a block of text, the favicon and app icons predate the August palette, and the four critters never appear outside the 3D games.

This work replaces every emoji that stands in for a picture with original artwork drawn for this site, and gives the hero the critters. Nothing structural moves. The palette, Fredoka, the candy buttons, the game boards and the zero-third-party rule all stay exactly as they are.

## The icon set

One original SVG per game, 45 files, at `icons/games/<slug>.svg` where `<slug>` is the game's folder name under `games/`.

Style rules, all checked by the test in `docs/tests/icons.test.js`:

- `viewBox="0 0 48 48"`, no `width` or `height` attributes (the page sizes it).
- Outlines in the ink colour `#33302e`, `stroke-width` 2.5, round joins and caps. Fills are flat: the site palette (`tokens.css` colours) plus this fixed set of extra fills, and nothing else: red `#ef4444`, yellow `#fbbf24`, green `#4ade80`, blue `#60a5fa`, pink `#ff8fab`, brown `#8b5e3c`, grey `#94a3b8`, white `#ffffff`.
- No `<text>` elements. Digits and letters are drawn as shapes, so they render the same on every device and inside an `<img>`.
- No gradients, filters, scripts, external references, `<image>` elements or embedded fonts.
- No two files are byte-identical, and no two games get the same picture (Count With Me and Dot to Dot currently share 🔢).
- Each icon must read at 36px, the phone size. Fine detail that disappears at that size is left out.
- Each file carries a one-line XML comment naming the game, and nothing else that a renderer would have to parse.

The pictures are chosen to say what the game is, not to be clever: a brain for Memory Match, a paint palette for Color Matcher, stacked number blocks for Count With Me, a dashed shape with numbered dots for Dot to Dot, a crayon for Drawing Pad, a lotus on water for Peekaboo Pond, and so on through the catalogue. The 14+ games keep a grown-up tone: a laser and mirror, a twisting cube, a cube stack with its plan view, a floating log, a molecule, a cannonball arc, an AND gate, an unfolded net.

The critters get four more files at `icons/critters/clover.svg`, `pip.svg`, `plum.svg` and `mango.svg`: the bunny, frog, baby dino and kitten from `games/shared/3d/critters.js`, drawn flat in the same ink-outline style, using their 3D colours (cream and pink, green, lilac with peach spikes, orange with pink inner ears). Same rules as the game icons except the box, which is `0 0 64 60`. These are pictures of the existing critters. The 3D models themselves are final and do not change.

The brand mark is one more file, `icons/mark.svg`: a cream play triangle sitting on a hard `--candy-coral` shadow inside a coral rounded square, with four confetti dots in yellow, periwinkle, green and pink. Box `0 0 64 64`.

## Where the icons appear

Icons are referenced as plain image files, never inlined or sprited. An `<img>` works over `file://` (a sprite's `<use href="file.svg#id">` does not in Chrome), gives one source of truth per picture, and is precached by the service worker without any change to the generator, whose precache walk already includes `.svg`.

- **Homepage cards** (`index.html`, hand-maintained): the `.game-icon` span keeps its tinted circle, and the emoji inside it becomes `<img src="icons/games/<slug>.svg" alt="" width="44" height="44">`. `styles.css` gains `.game-icon img { width: 44px; height: 44px; display: block; }` and, inside the existing 480px phone rule, `36px`, so the picture shrinks with its circle. A one-off script in the session scratchpad does the swap keyed on each card's `href`, and the test confirms afterwards that no `.game-icon` on the page still holds text.
- **Catalogue, 404 and For Grown-Ups** (generated by `node docs/build-pages.js` from `docs/catalogue.js`): the generator derives the icon path from `slug` and emits the same `<img>` in the card and in the For Grown-Ups table cell, with `../` or no prefix as the page's depth needs. Only the generator reads a game's `emoji` field, in exactly these three places, so the field is removed from every game entry once they change; the seven skill entries keep theirs, because the skill headings on For Grown-Ups are text in a heading rather than a picture of a game, and they stay.
- **Game-page titles** (all 45 `games/<slug>/index.html`): the title's emoji becomes `<img class="title-icon" src="../../icons/games/<slug>.svg" alt="" width="40" height="40">`. Two patterns exist and both are handled: `<h1><span aria-hidden="true">🧠</span> Memory Match</h1>` on the legacy pages, and `<h1>🧠 Memory Match</h1>` on the newer ones. Tic Tac Toe's trailing ❌ span is removed with the leading one. 2048 has no emoji and gains the image in front of its name. `components.css` gets one rule so the image sits on the text's centre line: `.title-icon { width: 1em; height: 1em; vertical-align: -0.12em; margin-right: 0.15em; }` scaled by the h1's own font size. The swap is scripted and targets only the first `<h1` in each file. Emoji used inside gameplay (balloons, fruit, animals on buttons) are not touched.

The `alt` is empty everywhere: the game's name is always beside the picture, and the span around it is already `aria-hidden`.

## The hero

On the homepage and the generated catalogue page:

- The 🎮 in the `<h1>` becomes the mark: `<img class="hero-mark" src="icons/mark.svg" alt="" width="44" height="44">` beside the words. The `<h1>` becomes an inline-flex row with a small gap, and `.hero-mark { width: 0.9em; height: 0.9em; }` sizes the mark from the heading's own clamped font size, so it stays on the text's centre line at every width. This is the coral mark from the review page's hero, used everywhere; the blueberry tab variant shown there is dropped so there is one mark.
- Confetti is CSS only: four layered `radial-gradient` dots in yellow, coral, periwinkle and green at low opacity on the navy band, with different tile sizes so they do not read as a grid. It lives in `styles.css` on `.hero`.
- The critters stand across the hero's bottom edge: `<ul class="hero-critters" aria-hidden="true">` with four `<img>` (Clover, Pip, Plum, Mango, in that order), absolutely positioned at the bottom of the hero so that about half of each head overlaps the cream page below. The hero's bottom padding grows to make room above them, and the first `.age-section` gains top padding so the heads do not touch its eyebrow. On phones (the existing 560px rule) the heads shrink to about 56px and the padding scales down with them. The hero stays short on a phone: the first row of cards must still be reachable with a short scroll, as the comment in `styles.css` already requires.
- No animation. The hover wiggle on cards stays as it is.

The For Grown-Ups and 404 heroes keep their text-only titles, because their emoji (👋, 🧭) are not pictures of a game and are fine as text.

## Cards stop stretching

`.game-grid` changes from `repeat(auto-fit, minmax(150px, 1fr))` to `repeat(auto-fill, minmax(150px, 190px))` with `justify-content: center`, so a row of two cards (the 2+ band) is two card-sized cards, centred, instead of two half-page slabs. The phone rule (`repeat(2, 1fr)` below 480px) is unchanged.

## Brand mark and app icons

- `favicon.svg` is replaced with the play-badge artwork, drawn at `0 0 64 64` with the same rules as `icons/mark.svg` (it can be the same file content).
- `icons/icon-192.png`, `icons/icon-512.png`, `icons/icon-maskable-512.png` and `apple-touch-icon.png` (180×180) are re-rasterised from the mark. The maskable icon draws the mark at 80% inside a full-bleed blueberry square so the safe zone is respected; the others are the rounded square on a transparent background, and the Apple icon on an opaque blueberry square (iOS ignores transparency). Rasterising uses the installed Chrome driven by puppeteer-core from the OS temp directory, as the 3D screenshots already do, with an element screenshot at the exact pixel size. Nothing new enters the repo.
- The homepage `theme-color` meta changes from `#c2410c` to `#2b2a5e`, which is what `manifest.json` already declares.

## Legacy gradients

Eight game pages still carry fifteen `linear-gradient` declarations from before the August restyle: balloon-pop, catch-falling-object, color-matcher, geography-explorer, memory-game, tic-tac-toe, whack-a-mole and word-scramble. Each occurrence is classified by reading it:

- **Decoration** (a card back, a button, a panel, a page background): replaced with a flat colour from the page's band tint and ink, in the existing candy style where it is a button. Memory Match's coral-to-teal card backs become a flat teal tint with the ink question mark, and their matched faces a flat green tint.
- **Game content** (anything the player reads as information, such as Color Matcher's mixing preview if it shows a blend): left alone, with a comment saying why.

This is the last step and is separable: the earlier steps ship on their own if it has to wait.

## Verification

`docs/tests/icons.test.js` (Node's built-in test runner, like the existing tests) checks:

1. Every `slug` in `docs/catalogue.js` has `icons/games/<slug>.svg`, and there are no icon files without a game.
2. Every icon file, critter and the mark obeys the style rules above: box size per folder (`0 0 48 48` for games, `0 0 64 60` for critters, `0 0 64 64` for the mark), allowed fill set (the `tokens.css` colours, the extra fills listed above and the ink for games and the mark; for the critters, additionally every hex colour that appears in `games/shared/3d/critters.js`), ink stroke, no `<text>`, no gradients or filters or scripts or external references, and no two files identical.
3. `index.html`, `games/index.html` and `404.html` have no `.game-icon` whose content is text, and every `<img>` inside one points at an existing file.
4. Every `games/<slug>/index.html` has a `.title-icon` image in its first `<h1>` pointing at its own icon.
5. `sw.js` lists every icon file (that is, the generator was re-run).

The look is judged by eye once: a contact sheet of all 45 icons plus the critters at 44px and 36px, rendered by headless Chrome from a throwaway page in the scratchpad. Icons that do not read at 36px are redrawn before the swap.

The existing suite (`node --test docs/tests/*.test.js`) must still pass, and `node docs/build-pages.js` must be re-run as the final step so the three generated pages and the precache list match the files on disk.

## Not changing

The palette and `tokens.css`, Fredoka, the candy buttons, the trust badges, the phone layout rules, the 3D critter models, every game board, the skill emojis on For Grown-Ups, the emoji inside gameplay, and the rule that no page makes a third-party request. All artwork is original SVG committed to the repo.
